01 Dify-style Service Workflow

Dify 워크플로우로 구현한 것처럼, 입력과 에이전트 노드를 연결했습니다.

가족 입력이 Router를 지나 각 에이전트 노드로 분기되고, 부모님 답변 후 DB와 Knowledge Retrieval을 거쳐 산출물로 이어지는 구조입니다.

Main Canvas

Start → Router → Agent Branches → Store → Knowledge → Output

S
가족 입력 수신
Start
부모님 답변, 자녀 질문, 사진, 일정이 워크플로우의 입력값으로 들어옵니다.
IF
입력 유형 라우터
Condition Router
입력이 답변인지, 질문인지, 사진인지, 일정인지 판단해 알맞은 에이전트로 분기합니다.
Q
Interviewer
Follow-up Agent
부모님 답변 뒤 자연스러운 꼬리질문을 만듭니다.
QQ
Question Queue
Question Rewrite
자녀 질문을 부모님이 답하기 쉬운 회상형 질문으로 바꿉니다.
V
Photo Agent
Vision Node
사진을 분석해 질문 후보를 만들고, 자녀 등록 후 공개합니다.
T
Calendar Trigger
Event Trigger
일정과 관련 기억을 찾거나 새 인터뷰 주제를 제안합니다.
부모님 답변 후 실행
A
Archivist
Structuring Node
원문을 보존하며 MemoryChunk로 구조화합니다.
✓
Verification
Guard Node
충돌, 중복, 불확실성을 표시합니다.
DB
InterviewRecord + RAG
Database / Knowledge Retrieval
답변, 질문 연결, 검수 상태를 저장하고 이후 검색 가능한 기억으로 색인합니다.
O
Output Router
Answer / Book Output
Digital Twin은 대화방을, Publication Agent는 기록집 미리보기와 최종 PDF를 만듭니다.
Dify처럼 보이도록 노드 타입을 Start, Router, Agent, Guard, Knowledge Retrieval, Output으로 나눴습니다. 단, 노드 내용은 Dearlog 실제 서비스 흐름에 맞췄습니다.
