# Dearlog 캡스톤 발표 패키지

## 1. 시연 시나리오

발표 시간은 3~5분을 기준으로 잡는다. 시작 전 `설정 > 발표 데모`에서 `발표용 데이터 불러오기`를 누르고 `네트워크 없이 시연`이 켜져 있는지 확인한다.

| 순서 | 화면 | 보여줄 기능 | 발표 멘트 |
| --- | --- | --- | --- |
| 1 | 설정 / 발표 데모 | 사전 DB 준비, 발표 준비 상태 | 실제 인터뷰 데이터가 저장돼 있다는 가정으로 안정적인 사전 DB를 불러옵니다. |
| 2 | 말씀 나누기 | 대화형 회상 기록, 사진 기반 회상 | 어르신은 양식을 채우는 대신 대화하듯 기억을 남깁니다. |
| 3 | 추억 보관함 / 가족 공간 | 태그, 사진, 가족 질문, 민감정보 마스킹 | 가족 공개 전 GPS 같은 민감정보는 원본 좌표 대신 확인 상태로 표시합니다. |
| 4 | 나의 분신 | 저장된 기억 기반 챗봇 답변 | 챗봇은 없는 이야기를 만들지 않고 저장된 기억을 근거로 답합니다. |
| 5 | 자서전 | 사전 자서전과 A5 인쇄용 PDF | 최종 결과물은 앱 안의 기록을 가족에게 전달 가능한 인쇄물로 바꿉니다. |

## 2. 인쇄물 점검

시연 전 `자서전 > 사전 자서전 불러오기 > 인쇄용 PDF`를 눌러 실제 파일을 생성한다.

| 항목 | 확인 기준 |
| --- | --- |
| 표지 | 제목, 저자명, 캡스톤 발표용 부제가 보인다. |
| 목차 | 6개 챕터가 순서대로 표시된다. |
| 본문 | A5 기준으로 문장이 너무 빽빽하지 않다. |
| 사진 페이지 | 대표 사진, 촬영 시기, 장소 추정 정보가 포함된다. |
| 개인정보 | GPS 원본 좌표가 직접 노출되지 않는다. |
| 가족 검수 | 가족 확인을 거친 인쇄물이라는 설명이 가능하다. |

## 3. 데모 데이터 구성

- 어르신: 김영자, 1950년대생
- 기억 카드: 시장, 서울역, 첫 월급, 가족 사진, 가족에게 남기는 말, 손녀와 바다
- 사진: 부산 시장, 서울역, 가족 사진, 송도 바다
- 가족 질문: 서울 첫날, 손주에게 남길 말, 손녀와 나들이
- 챗봇 추천 질문:
  - 처음 서울에 올라왔을 때 이야기를 들려주세요
  - 어머니와 시장에 갔던 날은 어떤 기억인가요?
  - 가족에게 꼭 남기고 싶은 말씀이 있으신가요?
  - 첫 월급을 받았을 때 어떤 마음이었나요?

## 4. 발표 안전장치

- 발표 데모 탭의 준비 상태가 모두 완료인지 확인한다.
- 네트워크가 불안정해도 챗봇은 오프라인 데모 응답으로 동작한다.
- GPS 좌표는 앱과 인쇄물에서 직접 보여주지 않는다.
- 발표 전 `발표용 데이터 초기화` 후 다시 불러오면 동일한 상태로 복구할 수 있다.

## 5. 제출 자료 구성

| 섹션 | 포함할 내용 |
| --- | --- |
| 서비스 개요 | Dearlog는 어르신의 기억을 대화, 사진, 가족 질문으로 수집해 자서전과 분신 대화로 확장하는 서비스다. |
| 사용자 여정 | 로그인, 회상 기록, 기억 정리, 가족 확인, 분신 대화, 자서전 생성, 사후 정책 설정. |
| 핵심 기술 | React, Zustand persist, RAG 검색 연결, 말투 프로필, PDF 생성, 동의/공개 범위 제어. 자세한 구조는 `docs/technical-architecture.md`를 참고한다. |
| 개인정보 설계 | 가족 공개 전 동의, 민감정보 마스킹, 사후 이용 정책, 로컬 데모 데이터 분리. |
| 시연 결과물 | 사전 DB 기반 챗봇 답변과 A5 인쇄용 자서전 PDF. |

## 발표 전 체크

- `npm run lint`, `npm test`, `npm run build` 통과
- 로컬 서버 실행 후 `/settings`에서 발표 데이터 준비
- 자서전 PDF 파일 생성 및 열람 확인
- 발표 질문 1개 이상을 직접 입력해 답변 근거 확인

| 3:20-4:30 | 결과물 제시 | 마지막으로 자서전 화면에서 사전 자서전을 불러오고 인쇄용 PDF를 생성합니다. 발표 결과물은 단순 앱 화면이 아니라 실제 가족에게 건넬 수 있는 A5 자서전입니다. |
| 4:30-5:00 | 마무리 | Dearlog는 기록, 가족 검수, 대화형 회상, 인쇄물 제작을 하나의 여정으로 연결해 기억을 오래 남기는 서비스를 목표로 합니다. |

## 7. 심사위원 예상 질문과 답변

| 질문 | 답변 |
| --- | --- |
| 실제 개인정보와 사후 데이터는 어떻게 보호하나요? | 현재 프로토타입은 로컬 저장 기반이며, 서비스 설계에서는 기억별 공개 범위, 가족 공개 동의, 민감정보 마스킹, 사후 이용 정책을 분리했습니다. GPS 같은 정보는 가족 공개 전 확인 상태로만 보여줍니다. |
| 챗봇이 사실과 다른 말을 하면 어떻게 하나요? | 분신 대화는 저장된 기억과 검색 연결을 근거로 답하도록 설계했습니다. 발표 데모에서도 근거가 없는 질문에는 기록된 기억이 없다고 답하게 만들어 환각 위험을 줄였습니다. |
| 어르신이 사용하기 어렵지 않나요? | 핵심 입력은 긴 폼이 아니라 휴대폰 로그인 후 대화형 회상과 사진 기반 회상입니다. 모바일 우선 화면, 큰 CTA, 짧은 단계 흐름을 기준으로 설계했습니다. |
| 기존 사진첩이나 메모 앱과 무엇이 다른가요? | Dearlog는 단순 보관이 아니라 가족 질문, 동의 관리, 근거 기반 분신 대화, 인쇄용 자서전까지 이어지는 전체 여정을 제공합니다. |
| 실제 서비스로 확장하려면 무엇이 더 필요한가요? | SMS 인증, 서버 저장소, 가족 초대 권한, 암호화, 백업, 인쇄 제휴, 의료·심리적 고위험 표현에 대한 안전 정책이 필요합니다. 캡스톤에서는 이 중 핵심 사용자 여정과 결과물을 검증합니다. |

## 8. PPT/포스터 핵심 문장

- 어르신의 기억을 대화로 기록하고, 가족에게 자서전으로 전달합니다.
- 사진, 가족 질문, 회상 인터뷰를 하나의 기억 카드로 정리합니다.
- 근거 없는 AI 답변이 아니라 저장된 기억에 기반한 분신 대화를 제공합니다.
- 앱 속 기록을 실제 A5 인쇄 자서전으로 완성합니다.
- 동의, 공개 범위, 민감정보 마스킹을 기억마다 함께 관리합니다.
