### 테스트 (커밋 `4eec25c`)

간헐적 1건 실패의 근본 원인을 특정했다. `vitest.config.ts`의 `testTimeout: 30000`은
RTL의 `waitFor`/`findBy`에 적용되지 않고, RTL은 자체 기본값 **1초**를 쓴다. 테스트 파일이
병렬로 도는 동안 jsdom 렌더가 1초를 넘기면 "0 times 호출됨" 같은 일반 단언 실패로 나타난다.
재현된 사례는 `src/pages/ChildPhotosScreen.test.tsx`의 GPS 마스킹 테스트이며 격리 실행에서는
8/8 통과했다. `vitest.setup.ts`에 `configure({ asyncUtilTimeout: 5000 })`을 추가해 129개
호출부를 한 번에 덮었다. 개별 파일에 있던 `{ timeout: 3000 }` 임시 조치 2곳도 이것으로 대체된다.

공유 SQLite DB나 업로드 디렉터리 경합은 **원인이 아님을 확인했다**. 두 서버 테스트 파일은
각자 `os.tmpdir()`에 다른 접두사로 DB를 만들고, pool `forks` + `isolate: true`라 프로세스가
분리된다.

### 알려진 문제로 남긴 것

- **Twilio 웹훅 서명 미검증**: `/twilio/status`는 서명을 전혀 확인하지 않고
  `req.body.CallStatus`를 일정 상태에 기록한다. `/twilio/voice`는 `TWILIO_AUTH_TOKEN`이
  비어 있으면 검증을 건너뛴다(fail-open). 위 3번에서 이 계열을 삭제하기로 하면 함께 사라진다.
- **`/twilio/media` WebSocket 무인증**: 연결만 하면 OpenAI Realtime 소켓을 연다.
- **전역 에러 핸들러가 `error.message`를 그대로 반환**: 잘못된 id로 Prisma 오류가 나면
  테이블·컬럼·제약 이름이 응답에 노출된다.
- **`POST /api/auth/phone`에 OTP·레이트리밋 없음**: 전화번호와 이름만 맞으면 30일 토큰이 나온다.
  데모용으로 의도된 것으로 보이나, 실제 파일럿 전에는 최소한 시도 제한이 필요하다.
- **출판 미리보기 재시도 무한 루프 가능**: `PUBLICATION_PREVIEW_MAX_ATTEMPTS`가
  `isRecoverablePreviewJobError`로 감싸여 있어 복구 가능 오류에서는 상한이 적용되지 않는다.
- **PDF 생성 실패 시 `generating` 상태 고착**: `failed` 전이가 없어 UI가 진행 중과 구분 못 한다.
- **`common_questions` 전역 수정 가능**: 시니어 아무나 `PATCH /api/questions/:id`로 모든 가족이
  공유하는 공통 질문 텍스트를 바꿀 수 있다. `DELETE`는 이미 막혀 있어 누락으로 보인다.
- **Puppeteer 테스트 3건이 부하 시 30초 초과**: `renderHtmlToPdf`가 호출마다 Chrome을
  새로 띄운다. 프로세스당 1회로 메모이즈하면 테스트와 운영 양쪽에 이득이지만, 브라우저
  수명 관리 변경이라 별도로 검토해야 한다.
- **접근성**: 인터뷰 통화 수락/거절 버튼이 아이콘만 있어 스크린리더에서 이름 없는 버튼으로
  읽힌다(시니어 대상 화면의 핵심 조작). 동의 토글 2곳도 같은 문제이며,
  `DemoSettingsScreen`의 동일 컴포넌트는 이미 `label` prop을 받는다. 달력 화살표는 36px로
  최소 탭 타깃 44px 미만이다.
- **챕터 정의 3중화**: `server/domain/constants.ts`(7개), `demo-seed-adapter.ts`(5개),
  `ChildQuestionsScreen.tsx`(5개)가 같은 id에 서로 다른 한국어 제목을 쓴다. 어느 쪽이
