### 테스트 (커밋 `4eec25c`)

간헐적 1건 실패의 근본 원인을 특정했다. `vitest.config.ts`의 `testTimeout: 30000`은
RTL의 `waitFor`/`findBy`에 적용되지 않고, RTL은 자체 기본값 **1초**를 쓴다. 테스트 파일이

8/8 통과했다. `vitest.setup.ts`에 `configure({ asyncUtilTimeout: 5000 })`을 추가해 129개
호출부를 한 번에 덮었다. 개별 파일에 있던 `{ timeout: 3000 }` 임시 조치 2곳도 이것으로 대체된다.

공유 SQLite DB나 업로드 디렉터리 경합은 **원인이 아님을 확인했다**. 두 서버 테스트 파일은
각자 `os.tmpdir()`에 다른 접두사로 DB를 만들고, pool `forks` + `isolate: true`라 프로세스가
분리된다.

## 접근성과 파일럿 전 하드닝 (커밋 아래 참조)

접근성:

- 인터뷰 **통화 수락/거절 버튼**이 아이콘만 있어 스크린리더에서 둘 다 이름 없는 버튼으로
  읽혔다. 시니어 대상 화면의 핵심 조작이라 `aria-label`을 붙였다.
- 동의 화면과 마이페이지의 `Toggle`이 `aria-pressed`만 있고 이름이 없었다.
  `DemoSettingsScreen`의 같은 컴포넌트가 이미 쓰던 `label` prop 형태로 통일했다.
- 캘린더 월 이동 화살표가 36px로 최소 탭 타깃 44px 미만이었다. 44px로 올리고
  `aria-label`을 붙였다. 캘린더·마이페이지 뒤로 버튼에도 이름을 붙였다.

전체 화면의 아이콘 전용 버튼을 다시 훑었는데, 처음 18곳이 걸린 것은 **모두 오탐**이었다.
검사 정규식이 `{...}` 표현식을 지웠고 거기에 실제 표시 텍스트(`{children}`,
`{isGenerating ? … : '자서전 생성하기'}`)가 들어 있었다. 실제 이름 없는 버튼은 위 항목이 전부다.

하드닝:

- `POST /api/auth/phone`에 시도 제한을 붙였다. 번호별 10회 / IP별 100회 / 10분 창이며
  `429`와 `Retry-After`를 반환한다. IP 한도를 훨씬 높게 둔 이유는 한 가족이 공유기나 통신사
  NAT 뒤에서 같은 IP로 잡히기 때문이다. 번호를 노린 대입은 번호 한도가 막는다.
  프로세스 메모리 기반이라 다중 인스턴스에서는 공유 저장소가 필요하다(`ponytail:` 주석으로 표시).
- 전역 에러 핸들러가 `statusCode`가 명시된 오류(`httpError`)의 메시지만 반환하도록 바꿨다.
  그 외에는 서버 로그에만 남기고 일반 메시지를 내보낸다. 실제로 확인해 보니 잘못된
  `chapterId` 하나로 Prisma 예외 전문이 응답에 실려 있었다.

  공통 질문은 `seniorId`가 없어 모든 가족이 같은 행을 공유하므로, 시니어 한 명이 고치면
  다른 가족의 화면까지 바뀌었다. `DELETE`는 같은 이유로 이미 막혀 있었고 `PATCH`만 빠져 있었다.
